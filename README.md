# Image To Bin

将图片批量转换为可写入 Flash 的 BIN 文件，并生成固件使用的 C 头文件与 CSV 地址表。

## 打开工具

- 在线使用时，打开 [Image To Bin 网页版](https://qingyu4012.github.io/Image-To-Bin/)。
- 离线使用时，下载或克隆仓库，双击 `index.html`。推荐使用桌面 Chrome 或 Edge，以便选择保存目录。

图片预览、转换、工程保存和 ZIP 打包均在浏览器本地执行，原图和导出文件无需上传。

## 转换与导出

1. 拖入或批量选择原图，或使用「导入目录」读取目录及子目录中的图片。点击缩略图可以切换上一张或下一张，并按适应窗口、1:1 或手动缩放查看像素。第一列的勾选框用于批量上移、下移或删除，「启用」列决定资源是否进入 BIN。列表中也可添加预留区或清空资源。
2. 选择颜色格式、扫描方向、字节序和 Flash 布局。资源地址留空时按表格顺序对齐分配，手动地址会保留。至少启用一项有效资源，且地址无重叠、无容量超限后，即可保存。
3. 点击「选择保存路径」选定目录，再点击「保存工程」。同一目录会收到以下五个文件。

   | 默认文件名 | 用途 |
   | --- | --- |
   | `system_ui_images.bin` | 从地址 `0x000000` 开始烧录，未使用的地址按设置填充 |
   | `system_ui_images_map.h` | 固件使用的资源地址、像素地址、长度和宽高 |
   | `system_ui_images_map.csv` | 核对顺序、源图和 Flash 地址 |
   | `system_ui_images.itbproj` | 包含原图、资源顺序和转换设置，可重新打开 |
   | `system_ui_images.zip` | 内含同一批次的 BIN、H、CSV 和工程文件 |

   BIN、工程和 ZIP 会随 BIN 文件名设置同步改名。浏览器缺少目录写入接口时，「保存工程」会下载 ZIP。

## 工程保存与迁移

在同一个浏览器配置和网页地址上重新打开，会自动恢复上次的图片、顺序、取模配置、主题和已记住的保存目录。再次保存时，浏览器可能要求重新确认目录的写入权限。

从本地页面迁移到 GitHub Pages、换浏览器或换电脑时，先保存 `.itbproj`，再在目标页面点击「打开工程」恢复原图、资源顺序和转换设置。可从 ZIP 中提取 `.itbproj`，保存目录需重新选择。旧桌面工具的 `.htbproj` 指向中间头文件，迁移时需要重新导入原图。

## 默认取模设置与浏览器兼容性

主题可选择跟随系统、浅色或深色。默认取模设置沿用 H20 的 `SYSTEM_UI` 资源格式，使用 25Q40、256 B 对齐、RGB565 大端和 8 B 图片头。固件读像素时使用头文件中的 `*_DATA_ADDR`。启用 `*_MAP_IMPLEMENTATION` 的定义应位于单个 C 源文件中。

浏览器支持的图片格式以本机解码能力为准。如果 RGBA 类取模回退到 Canvas 2D，完全透明或半透明像素的 RGB 通道可能因浏览器预乘和舍入而变化。

## 发布到 GitHub Pages

网页入口为 `index.html`，同目录需要 `styles.css`、`image-converter.js`、`project-storage.js`、`zip-export.js` 和 `app.js`。资源均通过相对路径加载，可以直接从仓库根目录发布。

在 GitHub 仓库的 **Settings → Pages** 中选择 **Deploy from a branch**，发布来源设为 `main` 和 `/(root)`。部署完成后，在 Pages 设置中可查看站点的 HTTPS 地址。日常更新推送到 `main` 后会触发重新部署。

`header_to_bin/` 和 `image_to_header/` 是旧版 Python 桌面工具的独立目录，已在网页版仓库中忽略。
